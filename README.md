# TAPE ECHO · 磁带回响

一个单文件的 2D 平台解谜原型。你捡到一盘磁带：按 E 录下自己 5 秒的动作，再按 E，"过去的你"就会在原地重演这段动作——他是个**实体**，能踩、能挡、能替你按住开关。

用这个机制帮自己过 6 个关卡。零依赖，双击即玩。

## 按键

| 键 | 作用 |
|---|---|
| A / D | 左右移动 |
| 空格 | 跳（长按跳更高） |
| Shift | 加速冲刺 |
| F | 举起 / 放下箱子 |
| G | 扔出箱子 |
| **E** | **录制 / 回放**（核心键） |
| **Q** | 倒带：清空磁带，**回声留在场上**；磁带已空时再按一次 = 清掉所有回声 |
| **R** | 重来本关：世界复位，磁带保留、回声清空 |
| Esc | 设置（音量、改键、录制时长、自定义关卡、跳关） |

屏幕下方也有一排可点的按钮，改过键位之后按钮标签会跟着变。

## 三个决定这游戏成不成立的设计

**1. 录的是「输入」不是「轨迹」。** 如果只回放坐标，过去的你就只是一段会穿墙的动画。录输入意味着回声跑完整套物理——他会被箱子挡住、会抓空、能踩在他头上。因为逻辑是固定 60Hz 步长，重演完全确定。

**2. 回放起点 = 你按下录制时的位置。** 所以磁带是一件**可重复使用的确定性道具**：配合 R 重置世界，就能做出"让过去的你替你扔箱子"这种谜题。

**3. 回声播完磁带后定格留在场上，不消失。** 这是单磁带能叠出三个回声的前提，也让「站到回声头上再录一段」成为可能——新回声的起点就是你头顶那个坐标，直接叠上去，不需要在空中对接。

另外角色之间做了**移动平台式传递**：站在回声头上时，他跑你会跟着平移，他跳你会被顶起来。所以"录一段先站着、然后起跳"，回放后踩上去等他起跳，等于白捡一次二段跳。

## 教程关卡

| 关 | 名字 | 要用到什么 |
|---|---|---|
| 01 | 按下不放 | 压力板必须有人一直踩着——让过去的你替你踩 |
| 02 | 垫脚石 | 回声是实体，踩着他的头跳上台阶 |
| 03 | 三双手 | 两块板要**同时**被踩住门才开，必须放两个回声 |
| 04 | 抛物线 | 限时门只开 1 秒而你离得太远：录下投掷 → R 重置 → 站到门边放 |
| 05 | 过河与登顶 | 桥要有人踩着板；过河后回声当垫脚石 |
| 06 | 三人梯 | 叠三层人梯摘星星（两层差 15px，够不到） |

**设计原则**：凡是"录制过程中就完成目标"的关卡，都不需要磁带——你录完那刻门已经开了，直接走过去就行，机制就成了摆设。所以谜题必须要求**同时性**。每一关的仿真测试里都有对应的反例验证。

## 做自己的关卡：editor.html

可视化编辑器，不用写代码：

- 拖放摆放地面/墙、箱子、压力板、门（可切成"桥"）、靶心、尖刺、出口、出生点；10px 网格吸附，拖右下角改尺寸，Delete 删除
- 右侧改数值：压力板绑几号门、踩住才开还是踩过锁开；靶心开门几秒；出口是不是星星
- 关卡列表：新建 / 复制 / 删除，改名字和提示语
- 底部内嵌真游戏，改完点「试玩本关」立刻能玩

**改完怎么让游戏用上**（浏览器不允许网页写本地文件，所以要选一条）：

| 方式 | 操作 | 生效范围 |
|---|---|---|
| 保存 | 编辑器点「保存」→ 打开 index.html | 当前浏览器 |
| 复制 JSON | 编辑器复制 → 游戏 Esc → 自定义关卡 → 粘贴 → 载入 | 当前浏览器，会存住 |
| 写入 index.html | 编辑器点「写入 index.html」→ 下载 → 覆盖原文件 | **永久**，发布用这条 |
| 分享链接 | 编辑器「生成分享链接」（单关约 580 字符） | 拿到链接的人 |

游戏里 Esc → 「回到内置」随时还原成自带 6 关。

## 发布到网上

见 **[发布指南.md](发布指南.md)**，四种方式：Notion `/html` 块（最快）、GitHub Pages（免费正式网址）、Netlify / Vercel 拖拽（30 秒）、或者让我一句话发布。

要点：游戏是**完全自包含**的单文件（无 fetch、无外链字体、无内联事件属性），所以能直接塞进 Notion 的 HTML block 里跑，匿名访客也能玩。但 Notion 的沙箱**没有 localStorage**，所以自定义关卡必须先「写入 index.html」烧进源码再上传。

## 改完代码必跑一次测试

```bash
cd tape-echo
node sim-test.js
```

这是无头仿真：把 `index.html` 里的真实游戏逻辑抽出来在 Node 里跑，用脚本模拟按键走完每一关。会验证：

- 6 关全部可解
- "不用磁带过不去""回声数量不够过不去"的反例
- 编辑器内置关卡与游戏关卡数据完全一致
- 分享链接能载入、编辑器改动写入游戏的三条通路

**关卡数值很敏感**（比如跳跃实测高度 82.5px，不是解析公式算出的 87px），肉眼看不出还能不能通关，所以改了关卡或物理一定要跑。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 游戏本体，单文件零依赖（HTML + CSS + Canvas 2D，约 1400 行） |
| `editor.html` | 可视化关卡编辑器，单文件零依赖 |
| `sim-test.js` | 无头仿真测试，`node sim-test.js` |
| `发布指南.md` | 发布到 Notion / GitHub Pages / Netlify 等的操作步骤 |

技术细节：固定 60Hz 逻辑步长 + 渲染插值；输入走「动作层」抽象（`binds{动作:[键码]}`），所以改键和屏幕按钮能共用一套逻辑；音乐是 WebAudio 程序生成的循环，没有外部音频文件。
